The **Triage** view is the primary workspace for reviewing and managing crashes and errors for a selected project. When you open the **Web Console**, the Triage view is displayed by default.

Triage organizes incoming crashes and errors into **fingerprints**, allowing you to review related error occurrences as a single group rather than investigating each occurrence individually. A fingerprint is a hash generated by Backtrace's deduplication algorithms and represents a unique error with a common root cause.

From the Triage view, you can filter fingerprints, review aggregated information about errors, and take actions to investigate, organize, and manage issues throughout their resolution.

## Errors Deduplication and Grouping

Backtrace uses deduplication algorithms to process incoming crashes and determine which error occurrences belong to the same underlying issue. Related occurrences are grouped together into a **fingerprint** based on their common characteristics and root cause.

This grouping allows large numbers of raw error entries to be represented as individual fingerprint groups in the Triage view. Instead of reviewing every occurrence separately, you can focus on the unique fingerprints that represent the underlying errors.

For each fingerprint, Triage provides aggregated information about the errors grouped under it. This information helps you understand the activity associated with an error and identify fingerprints that require further investigation.

## Review and Manage Fingerprints

Fingerprints provide a consistent way to track and manage a unique error from initial investigation through resolution. Because related error occurrences are grouped under the same fingerprint, you can use the fingerprint as the central reference when investigating an issue and coordinating its resolution.

From the **Triage** view, you can take the following actions on a fingerprint:

* **Filter by status:** Use the fingerprint's current state to focus on issues that are **Open**, **In Progress**, **Muted**, or **Resolved**. This helps you identify which fingerprints require investigation, which are actively being worked on, and which have already been addressed. For more information, see **[View & Manage Fingerprint Status](/docs/error-reporting/triage/view-manage-fingerprint-status.md)**
* **Review fingerprint details:** Open the fingerprint's **Details** view to get additional context about the error. The Details view provides information about attributes associated with the crashes and the instances included in the fingerprint. It also provides access to actions such as adding comments and tags or opening the latest trace in the Debugger. For more information, see **[View Fingerprint Group Details](/docs/error-reporting/triage/fingerprint-group-details.md).**
* **Investigate in the Debugger:** Open the fingerprint's latest trace in the **Debugger** to inspect the error and its callstack. This provides a focused view for investigating where the error occurred. For more information, see **[View Fingerprint in Debugger](/docs/error-reporting/triage/fingerprint-in-debugger.md)**
* **Assign responsibility:** Assign the fingerprint to a user in Backtrace when someone needs to take responsibility for investigating or resolving the issue. This makes the responsible user identifiable from the fingerprint.
* **Link to an issue:** Create an issue in a third-party system, such as Jira or GitHub Issues, and associate it with the fingerprint. The linked issue contains information about the fingerprint and provides a way to continue tracking the issue outside Backtrace.
* **Add comments and tags:** Use comments to document investigation findings, updates, or other relevant information about the fingerprint. Apply tags to group and classify fingerprints according to your team's investigation needs.
* **Merge related fingerprints:** If two or more fingerprints represent the same underlying issue, merge them to group future incoming errors into a single fingerprint. If fingerprints were grouped incorrectly or should no longer be combined, they can be unmerged from the fingerprint's Details view.

For more information about assigning fingerprints, linking issues, adding comments and tags, and merging or unmerging fingerprints, see **[Other Actions](/docs/error-reporting/triage/other-action.md)**
